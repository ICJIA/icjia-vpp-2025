# Routes Configuration Documentation

## Overview

The routes configuration system automatically discovers and catalogs all pages in the Violence Prevention Plan for Illinois: 2025-2029 project, providing a comprehensive site map with metadata for routing, navigation, and search functionality.

## Purpose

This system serves multiple critical functions:
- **Page Discovery**: Automatically finds all content and Vue pages during build
- **Metadata Extraction**: Extracts titles, descriptions, and other metadata from each page
- **Route Mapping**: Creates a complete catalog of all available routes
- **Search Integration**: Provides data for the search indexing system
- **Navigation Support**: Supplies metadata for dynamic navigation generation

## Generation Process

### Automatic Generation

The routes configuration is automatically generated during:
- `yarn dev` - Development server startup
- `yarn build` - Production build
- `yarn generate` - Static site generation

### Generation Steps

1. **Load Configuration**: Reads routing settings from `config/site.config.json`
2. **Scan Content Files**: Discovers all markdown files in the `content/` directory
3. **Scan Vue Pages**: Discovers all Vue components in the `pages/` directory
4. **Extract Metadata**: Extracts titles and metadata from each discovered file
5. **Apply Blacklisting**: Excludes files matching blacklist patterns
6. **Deduplicate Entries**: Merges entries that map to the same URL path
7. **Generate Output**: Creates configuration files in both `config/` and `public/` directories

## Page Discovery

The system uses glob patterns to discover pages in two main directories:

### Content Discovery (`content/**/*.md`)

- Scans all markdown files in the content directory
- Extracts frontmatter metadata (title, description, etc.)
- Maps content files to their corresponding URL paths
- Handles nested directory structures

### Vue Page Discovery (`pages/**/*.vue`)

- Scans all Vue components in the pages directory
- Extracts titles from `useHead()`, `useSeoMeta()`, and JSDoc comments
- Maps Vue files to their corresponding URL paths
- Handles dynamic routes and nested layouts

## Page Types

### Content Pages
Pages that exist only as markdown files in the `/content/` directory.

### Vue Pages
Pages that exist only as Vue components in the `/pages/` directory.

### Combined Pages
Pages that have both a markdown file in `/content/` and a Vue component in `/pages/` for the same route.

## Metadata Extraction

### From Markdown Files
- **Title**: Extracted from frontmatter `title` field
- **Description**: Extracted from frontmatter `description` field
- **Custom Fields**: Any additional frontmatter fields are preserved

### From Vue Files
- **Title**: Extracted from `useHead({ title: ... })` calls
- **Description**: Extracted from `useSeoMeta({ description: ... })` calls
- **JSDoc**: Extracted from component JSDoc comments

## Blacklisting

Files matching blacklist patterns are excluded from the routes catalog:

```json
{
  "blacklist": {
    "vue": ["sandbox.vue", "sandbox-*.vue"],
    "markdown": ["sandbox.md", "sandbox-*.md"]
  }
}
```

## Runtime Access

### Using the Composable

```vue
<script setup>
const { config, pages, loading, error } = useSiteConfig();

// Access all pages
console.log(pages.value);

// Access only content pages
console.log(contentPages.value);

// Access site statistics
console.log(stats.value);
</script>
```

### API Reference

| Property | Type | Description |
|----------|------|-------------|
| `config` | Ref | Complete routes configuration object |
| `pages` | ComputedRef | Array of all discovered pages |
| `contentPages` | ComputedRef | Array of content-only pages |
| `vuePages` | ComputedRef | Array of Vue-only pages |
| `combinedPages` | ComputedRef | Array of pages with both content and Vue files |
| `stats` | ComputedRef | Statistics about discovered pages |
| `loading` | Ref | Loading state indicator |
| `error` | Ref | Error state if configuration fails to load |

### Helper Methods

| Method | Parameters | Description |
|--------|------------|-------------|
| `findPageByPath(path)` | `string` | Find a specific page by its path |
| `findPagesByType(type)` | `string` | Find pages by type ('content', 'vue', 'combined') |
| `findPagesByPattern(regex)` | `RegExp\|string` | Find pages matching a regular expression |

## Integration Points

### Search System
The routes configuration provides page metadata for the search indexing system, ensuring all discoverable pages are included in search results.

### Navigation
Dynamic navigation components can use the routes configuration to build menus and breadcrumbs automatically.

### SEO
The metadata extracted during route discovery is used for SEO optimization and social media sharing.

### Sitemap Generation
The routes configuration serves as the primary data source for XML sitemap generation, providing:
- Complete list of all discoverable pages
- Page metadata including titles and paths
- Source file information for lastmod dates
- Integration with blacklist patterns for exclusions

## File Locations

- **Config**: `/config/routes.config.json` (build-time access)
- **Public**: `/public/config/routes.config.json` (runtime access)
- **Generator**: `/scripts/generate-site-config.js` (generation script)

## Best Practices

### Configuration Management
1. **Blacklist Maintenance**: Regularly review and update blacklist patterns
2. **Title Quality**: Ensure all pages have meaningful, descriptive titles
3. **Metadata Completeness**: Include descriptions for all pages

### Performance Considerations
1. **Build Time**: Large numbers of pages may increase build time
2. **Bundle Size**: The routes configuration is included in the client bundle
3. **Caching**: The configuration is cached during development for performance

## Troubleshooting

### Common Issues
- **Missing Pages**: Check blacklist patterns and file naming conventions
- **Incorrect Titles**: Verify frontmatter and useHead() implementations
- **Build Failures**: Check for syntax errors in markdown frontmatter

### Debug Information
Enable detailed logging by setting the logging level to 'Detailed' in the generation script.

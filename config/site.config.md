# Site Configuration Documentation

This document provides comprehensive documentation for the site configuration system that automatically discovers and catalogs all pages in the Violence Prevention Plan for Illinois: 2025-2029 application.

## Purpose and Overview

The site configuration system serves as a centralized catalog of all pages in the application, providing a complete site map with metadata that can be used for:

1. **Navigation Systems**: Automatic generation of site navigation menus and breadcrumbs
2. **Search Enhancement**: Integration with the search indexing system for comprehensive content discovery
3. **Site Analytics**: Understanding the structure and scope of the application
4. **Content Management**: Tracking all content sources and their relationships
5. **Build Validation**: Ensuring all pages are properly configured and accessible
6. **SEO Optimization**: Generating sitemaps and metadata for search engines

The system automatically scans both Nuxt Content markdown files (`content/**/*.md`) and Vue page components (`pages/**/*.vue`), extracting metadata and generating a unified catalog that represents the complete site structure.

## File Structure

The site configuration system consists of two main files:

### `site.config.base.json` (Manual Configuration)

This file contains the base configuration settings that control how the site configuration is generated:

```json
{
  "baseUrl": "https://vpp-2025.netlify.app/",
  "blacklist": {
    "vue": ["sandbox.vue", "sandbox-*.vue"],
    "markdown": ["sandbox.md", "sandbox-*.md"]
  },
  "titleExtraction": {
    "fallbackPattern": "Violence Prevention Plan for Illinois: 2025-2029",
    "maxLength": 100
  },
  "summary": {
    "projectName": "Violence Prevention Plan for Illinois: 2025-2029",
    "description": "Comprehensive site configuration for automatic page discovery and cataloging",
    "version": "1.0.0"
  }
}
```

### `site.config.json` (Auto-Generated)

This file is automatically generated during the build process and contains the complete site catalog:


## Generation Process

The site configuration is automatically generated during the following build commands:

- **`npm run dev`**: Generates configuration before starting the development server
- **`npm run build`**: Generates configuration before building for production
- **`npm run generate`**: Generates configuration before static site generation

### Build Integration

The generation process is integrated into the build pipeline through package.json scripts:

```json
{
  "scripts": {
    "dev": "npm run create:site-config && nuxt dev --port=8000 -o",
    "build": "npm run create:site-config && nuxt build",
    "generate": "npm run create:site-config && nuxt generate",
    "create:site-config": "node scripts/generate-site-config.js"
  }
}
```

### Generation Steps

1. **Load Base Configuration**: Reads settings from `config/site.config.base.json`
2. **Scan Content Files**: Discovers all markdown files in the `content/` directory
3. **Scan Vue Pages**: Discovers all Vue components in the `pages/` directory
4. **Extract Metadata**: Extracts titles and metadata from each discovered file
5. **Apply Blacklisting**: Excludes files matching blacklist patterns
6. **Deduplicate Entries**: Merges entries that map to the same URL path
7. **Generate Output**: Creates configuration files in both `config/` and `public/` directories

## Page Discovery

The system uses glob patterns to discover pages in two main directories:

### Content Discovery (`content/**/*.md`)

- Scans all markdown files recursively in the `content/` directory
- Extracts frontmatter metadata using the `gray-matter` library
- Converts file paths to URL paths (e.g., `content/about.md` → `/about`)
- Handles index files (e.g., `content/index.md` → `/`)

### Vue Page Discovery (`pages/**/*.vue`)

- Scans all Vue components recursively in the `pages/` directory
- Follows Nuxt.js routing conventions for path generation
- Extracts metadata from component scripts and JSDoc comments
- Handles dynamic routes and nested page structures

## Title Extraction

The system uses multiple strategies to extract meaningful titles from different file types:

### Markdown Files

Titles are extracted from frontmatter metadata:

```yaml
---
title: "About Us - Violence Prevention Plan"
description: "Learn about our mission and approach"
---
```

If no title is found in frontmatter, a fallback title is generated from the file path.

### Vue Components

The system attempts to extract titles using several methods, in order of priority:

1. **useHead() Calls**: Direct title definitions
   ```javascript
   useHead({
     title: 'Search - Violence Prevention Plan'
   });
   ```

2. **Computed useHead() Calls**: Dynamic title generation
   ```javascript
   useHead({
     title: computed(() => `${pageTitle.value} - Violence Prevention Plan`)
   });
   ```

3. **useSeoMeta() Calls**: SEO metadata definitions
   ```javascript
   useSeoMeta({
     title: 'Community Outreach Programs'
   });
   ```

4. **JSDoc @page Annotations**: Documentation-based titles
   ```javascript
   /**
    * @page Youth Intervention Programs
    */
   ```

5. **Component Name Patterns**: Extracted from JSDoc comments
   ```javascript
   /**
    * Search Page Component
    * Provides search functionality for the site
    */
   ```

6. **Default Title Variables**: Fallback values in component scripts
   ```javascript
   const defaultTitle = 'Youth Intervention';
   ```

### Fallback Title Generation

When no title can be extracted, the system generates a fallback title by:

1. Converting the URL path to title case (e.g., `/projects/youth-intervention` → `Projects - Youth Intervention`)
2. Appending the base project name from configuration
3. Ensuring the title doesn't exceed the configured maximum length

## Runtime Access

The site configuration can be accessed at runtime using the `useSiteConfig()` composable:

### Basic Usage

```vue
<script setup>
const { config, pages, loading, error } = useSiteConfig();

// Wait for configuration to load
await loadConfig();

// Access all pages
console.log(pages.value);

// Access statistics
console.log(`Total pages: ${stats.value.totalPages}`);
</script>
```

### Advanced Usage

```vue
<script setup>
const {
  findPageByPath,
  findPagesByType,
  findPagesByPattern,
  contentPages,
  vuePages
} = useSiteConfig();

// Find a specific page
const aboutPage = findPageByPath('/about');

// Find all content pages
const allContentPages = findPagesByType('content');

// Find pages matching a pattern
const projectPages = findPagesByPattern(/^\/projects\//);

// Access only content or Vue pages
const markdownPages = contentPages.value;
const componentPages = vuePages.value;
</script>
```

### Composable API Reference

| Property/Method | Type | Description |
|----------------|------|-------------|
| `config` | Ref | Complete configuration object |
| `loading` | Ref | Loading state indicator |
| `error` | Ref | Error state if loading fails |
| `pages` | ComputedRef | Array of all pages |
| `contentPages` | ComputedRef | Array of content (markdown) pages |
| `vuePages` | ComputedRef | Array of Vue component pages |
| `stats` | ComputedRef | Statistics object |
| `summary` | ComputedRef | Project summary information |
| `baseUrl` | ComputedRef | Configured base URL |
| `loadConfig()` | Function | Manually trigger configuration loading |
| `findPageByPath(path)` | Function | Find page by exact path match |
| `findPagesByType(type)` | Function | Find pages by type ('content', 'vue', 'combined') |
| `findPagesByPattern(regex)` | Function | Find pages matching a regular expression |

## Build-time Access

The configuration can also be accessed in Node.js scripts during build processes:

### Direct File Access

```javascript
import { promises as fs } from 'fs';
import path from 'path';

// Read the generated configuration
const configPath = path.join(process.cwd(), 'config/site.config.json');
const configContent = await fs.readFile(configPath, 'utf-8');
const siteConfig = JSON.parse(configContent);

// Use the configuration
console.log(`Found ${siteConfig.stats.totalPages} pages`);
```

### Using the Generator Class

```javascript
import SiteConfigGenerator from './scripts/generate-site-config.js';

// Create and run the generator
const generator = new SiteConfigGenerator();
const config = await generator.generate();

// Access the generated configuration
console.log(config.pages);
```

## Configuration Options

### Base Configuration (`site.config.base.json`)

| Property | Type | Description |
|----------|------|-------------|
| `baseUrl` | String | Base URL for generating full URLs (default: `https://vpp-2025.netlify.app/`) |
| `blacklist.vue` | Array | Patterns for Vue files to exclude from discovery |
| `blacklist.markdown` | Array | Patterns for markdown files to exclude from discovery |
| `titleExtraction.fallbackPattern` | String | Default title pattern when no title can be extracted |
| `titleExtraction.maxLength` | Number | Maximum length for generated titles |
| `summary.projectName` | String | Project name for metadata |
| `summary.description` | String | Project description for metadata |
| `summary.version` | String | Configuration version for tracking changes |

### Blacklist Patterns

Blacklist patterns support wildcards using the `*` character:

```json
{
  "blacklist": {
    "vue": [
      "sandbox.vue",           // Exact filename match
      "sandbox-*.vue",         // Wildcard pattern
      "draft-*.vue",           // Multiple wildcard patterns
      "test/**/*.vue"          // Directory patterns (not currently supported)
    ]
  }
}
```

### Title Extraction Options

```json
{
  "titleExtraction": {
    "fallbackPattern": "Violence Prevention Plan for Illinois: 2025-2029",
    "maxLength": 100,
    "preferMarkdownTitles": true,    // Prefer markdown over Vue titles
    "stripTemplateVariables": true   // Remove ${variable} from titles
  }
}
```

## Deduplication Logic

The system implements intelligent deduplication to handle cases where multiple files map to the same URL path (e.g., both `pages/about.vue` and `content/about.md` mapping to `/about`):

### Merge Strategy

1. **Path-based Grouping**: All entries with the same `path` are grouped together
2. **Title Prioritization**: Content (markdown) titles are preferred over Vue component titles
3. **Source Tracking**: All source files are preserved in a `sources` array
4. **Type Classification**: Pages are classified as 'content', 'vue', or 'combined'

### Example Deduplicated Entry

```json
{
  "title": "About Us - Violence Prevention Plan",
  "path": "/about",
  "fullUrl": "https://vpp-2025.netlify.app/about",
  "type": "combined",
  "sources": [
    {
      "type": "content",
      "source": "content/about.md",
      "title": "About Us - Violence Prevention Plan"
    },
    {
      "type": "vue",
      "source": "pages/about.vue",
      "title": "About - Violence Prevention Plan for Illinois: 2025-2029"
    }
  ]
}
```

### Statistics Impact

Deduplication affects the statistics in the generated configuration:

- `totalPages`: Count of unique paths (after deduplication)
- `contentPages`: Count of pages with markdown sources
- `vuePages`: Count of pages with Vue sources
- `combinedPages`: Count of pages with both markdown and Vue sources

## Usage Examples

### Creating a Site Navigation Menu

```vue
<template>
  <nav>
    <ul>
      <li v-for="page in navigationPages" :key="page.path">
        <NuxtLink :to="page.path">{{ page.title }}</NuxtLink>
      </li>
    </ul>
  </nav>
</template>

<script setup>
const { pages } = useSiteConfig();

// Filter pages for navigation (exclude certain paths)
const navigationPages = computed(() =>
  pages.value.filter(page =>
    !page.path.includes('/sandbox') &&
    page.path !== '/search'
  )
);
</script>
```

### Generating a Sitemap

```javascript
// scripts/generate-sitemap.js
import SiteConfigGenerator from './generate-site-config.js';

const generator = new SiteConfigGenerator();
const config = await generator.generate();

const sitemap = `<?xml version="1.0" encoding="UTF-8"?>
<urlset xmlns="http://www.sitemaps.org/schemas/sitemap/0.9">
${config.pages.map(page => `
  <url>
    <loc>${page.fullUrl}</loc>
    <lastmod>${config.generatedAt}</lastmod>
  </url>
`).join('')}
</urlset>`;

await fs.writeFile('public/sitemap.xml', sitemap);
```

### Page Metadata Validation

```javascript
// scripts/validate-pages.js
import { promises as fs } from 'fs';

const configPath = 'config/site.config.json';
const config = JSON.parse(await fs.readFile(configPath, 'utf-8'));

// Find pages without proper titles
const pagesWithoutTitles = config.pages.filter(page =>
  !page.title || page.title.includes('${') || page.title.length < 10
);

if (pagesWithoutTitles.length > 0) {
  console.warn('Pages with missing or poor titles:', pagesWithoutTitles);
}
```

## Best Practices

### Configuration Management

1. **Version Control**: Keep `site.config.base.json` in version control, but exclude the generated `site.config.json`
2. **Environment-Specific URLs**: Use different base URLs for development, staging, and production
3. **Blacklist Maintenance**: Regularly review and update blacklist patterns as the project evolves
4. **Title Quality**: Ensure all pages have meaningful, descriptive titles

### Performance Considerations

1. **File System Scanning**: The generation process scans the file system, so avoid deeply nested directory structures
2. **Title Extraction**: Complex regex patterns for title extraction can slow down generation
3. **Configuration Size**: Large configurations may impact runtime performance when loaded in the browser
4. **Caching**: The composable caches the configuration to avoid repeated network requests

### Integration Guidelines

1. **Consistent Patterns**: Use the same blacklist patterns across all build scripts (search, accessibility, site config)
2. **Error Handling**: Always handle cases where the configuration might not be available
3. **Fallback Values**: Provide sensible defaults when configuration data is missing
4. **Type Safety**: Consider adding TypeScript definitions for better development experience

## Limitations and Considerations

### Current Limitations

1. **Dynamic Routes**: Pages with dynamic parameters (e.g., `[slug].vue`) are not fully supported
2. **Runtime Content**: Content loaded dynamically at runtime is not included in the configuration
3. **External Content**: Content from APIs or external sources is not discovered
4. **Complex Routing**: Advanced Nuxt routing features may not be fully supported

### Future Enhancements

1. **Dynamic Route Support**: Better handling of parameterized routes
2. **Content Validation**: Built-in validation for page metadata and structure
3. **Incremental Updates**: Only regenerate configuration when files actually change
4. **TypeScript Support**: Full TypeScript definitions and type safety
5. **Plugin Architecture**: Extensible system for custom page discovery and metadata extraction

### Troubleshooting

#### Configuration Not Loading

```javascript
// Check if the configuration file exists
const { error } = useSiteConfig();
if (error.value) {
  console.error('Site configuration error:', error.value);
}
```

#### Missing Pages

1. Check if files are being blacklisted unintentionally
2. Verify file paths match the expected patterns (`content/**/*.md`, `pages/**/*.vue`)
3. Ensure files have proper extensions and are not hidden files

#### Incorrect Titles

1. Check frontmatter format in markdown files
2. Verify `useHead()` or `useSeoMeta()` calls in Vue components
3. Review title extraction patterns in the base configuration

#### Build Failures

1. Ensure all required dependencies are installed (`glob`, `gray-matter`)
2. Check file permissions for the `config/` and `public/` directories
3. Verify the base configuration file is valid JSON

## Migration Guide

### From Manual Page Lists

If you previously maintained manual lists of pages, you can migrate to the site configuration system:

1. **Remove Manual Lists**: Delete hardcoded page arrays from your components
2. **Update Components**: Replace manual lists with `useSiteConfig()` calls
3. **Configure Blacklisting**: Add any pages you want to exclude to the blacklist
4. **Test Navigation**: Verify that all navigation components work with the new system

### From Other Site Mapping Solutions

1. **Export Existing Data**: Export your current site structure to compare with generated configuration
2. **Map Field Names**: Update component code to use the new field names (`title`, `path`, `fullUrl`, etc.)
3. **Handle Type Changes**: Update code that depends on page type classification
4. **Validate Results**: Compare the generated configuration with your existing data

This comprehensive site configuration system provides a robust foundation for managing page metadata and site structure, with built-in deduplication and extensive customization options.
